ホーム ／ 機能ごとの使い方

インターネットに公開する

アプリに URL を付けて、誰でも開けるようにする方法です。

公開のながれ

はじめてのデプロイで「外からアクセスできるようにする」を選んだ人は

①と②は、すでに済んでいます。③のルールを、確認するだけです。

① Service で、ポートを決める

アプリが、お客さんを待っている窓口の番号(ポート)を、教えます。デプロイのパネルの Service タブで、ポートを追加します。

項目入れるもの
名前自由に付ける名前(例: web)。
ポートアプリが使う番号。nginx や、ふつうのホームページなら 80、アプリによっては 3000 や 8080 など。アプリの説明書で確認しましょう。
プロトコルtcp か udp。ホームページ(Web)は tcp。

保存 → 反映 で、有効になります。

インターネットに公開できるのは、tcp の、Web(HTTP)だけ

udp や、Web 以外の通信の公開は、まだ対応していません。

② Ingress を作る(公開の入口)

  1. 追加する

    構成図の右上 + 追加 → Ingress。

  2. URL を確認する

    「形容詞-色-動物」のような、覚えやすい名前の URL が、自動で付きます(例: https://brave-blue-fox.example.org)。自分で、名前を選ぶことは、できません。

この時点では、まだ公開されていません

Ingress を作っただけでは、ルールが空なので、URL を開いても、つながりません。次の③が、必要です。

③ ルールを作って、反映する

「どのパスに来たお客さんを、どのアプリのどのポートに、届けるか」を決めます。Ingress のカードを押して、右のパネルの「ルール」で、+ ルール追加。

項目意味例
パスURL の、ドメインより後ろの部分。/ は「全部」。/、/api
Service届け先のアプリ。動いている(active)で、tcp のポートがあるものが、選べます。nginx ・ service-…
ポート届け先のポート番号。80
  • パスは / で始めます。英数字と . _ ~ - % / が使えます(200 文字まで)。
  • 同じパスを、2 つ作ることは、できません。ルールは、50 件まで。
  • パスは「その文字で始まるもの、全部」に、一致します(/api は、/api/users にも一致)。長い(くわしい)パスが、先に使われます。/ と /api の両方を作ると、/api… は後者に、それ以外は前者に、行きます。
  1. 保存する

    保存。まだ、公開は変わりません。「反映待ち」の帯と、変更内容が出ます。

  2. 反映する

    反映。これで、公開されます。反映中は、状態が applying になります。

  3. URL を開く

    パネルの「公開 URL」を押します。数分かかることがあります。

URL は、https(暗号化された通信)で開きます

入口の手前で、暗号化の処理をしています。アプリ側で、特別な設定は、要りません。

公開をやめる

  • ルールを全部消して、反映 → URL を開いても、つながらなくなります(Ingress は残ります)。
  • Ingress を削除 → URL ごと、なくなります。あとで作り直しても、同じ URL にはなりません(新しい名前が付きます)。

どんなお客さんが来たかを見る

Ingress のパネルに、アクセスログ(1 回ずつのアクセスの記録)が出ます。くわしくは 様子を見る。
