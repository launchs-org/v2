# セキュリティ(不審なアクセスの確認、遮断、監査)

管理画面(`/admin` の「セキュリティ」)と、管理コンテナ(`admin/`)、auth で行う。仕様は [dev-docs/endpoints/admin.md](endpoints/admin.md)。

## できること
- **確認**: 「ログイン履歴」(失敗も、存在しない名前への試行も出る)と、「不審な IP」(期間内に失敗が多い IP。試されたユーザー名の種類が多いほど、総当たりの疑いが強い)、「アクセスログ」(全 ingress)。
- **遮断**: IP(または CIDR の範囲)をブロックする。期限は、解除するまで〜30 日。**効くのは、auth のログインとサインアップだけ**(403。履歴には、理由 `blocked` で残る)。ブロックした IP から、既にログインしている人や、利用者のアプリ(ingress)へのアクセスは、止めない。
  - 操作している自分の接続元を含む範囲は、ブロックできない(締め出し防止)。
  - 確認できない(DB の障害)ときは、通さずに、エラーにする。
- **監査**: 管理操作(ユーザーの停止・解除・ロック解除、招待の発行・取り消し、管理者の作成・昇格、IP のブロック・解除、全体のクォータの変更)を、`admin_audit_logs`(auth の DB)に追記する。画面では、読むだけ(更新も削除もしない)。

## 仕組み
- 表は auth の DB(`migrations/auth/000003`): `blocked_ips`(範囲は `cidr` 型)、`admin_audit_logs`。
- ブロックを書く・監査ログを読むのは、管理コンテナ(`AUTH_DATABASE_URL` で auth の DB にもつなぐ)。ブロックを読んで拒否するのは、auth(`IPBlockRepository`)。
- auth の管理 API とコマンドの操作は、auth が、監査ログに書く(コマンドは、操作した人が `command`)。管理コンテナの操作は、管理コンテナが書く。
- 監査ログを保存できなくても、操作は止めない(警告のログを残す)。

## 限界と、これから
- **アプリへのアクセス(Traefik)の遮断は、まだ**(Traefik 側のプラグインか、Cloudflare の規則が要る)。
- 本番で、auth が見る接続元の IP は、`AUTH_TRUSTED_PROXY_CIDRS` を正しく設定したときだけ、本当のクライアントの IP になる(合っていないと、プロキシの IP をブロックしてしまう)。
- 管理者かどうかは、管理コンテナでは access token の `role`(最大 15 分の遅れ)。
