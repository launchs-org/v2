## ボリューム(消えないデータの置き場所)

:::note info なぜ必要?
アプリは、更新や再起動のたびに、**作り直されます**。そのとき、アプリの中に書いたデータは、**消えます**。データベースの中身や、アップロードされた画像のように、**残したいデータ**は、ボリュームに置きます。
:::

### 作る

:::steps
1. **追加する**

   構成図の右上 [[+ 追加]] → [[ボリューム]]。

2. **名前と大きさを決める**

   名前は、**英数字とハイフン**(1〜64 文字)。大きさは **MB** で入れます(1 GB = 1024 MB)。1 つあたりの上限は、初期値で **5120 MB(約 5 GB)** です。
:::

### アプリにつなぐ(マウント)

デプロイのパネルの [[マウント]] タブで、**どのボリュームを、アプリの中の、どのフォルダに置くか**を決めます。

- **マウント先**は、`/` から始まる、フォルダ(ファイル)のパスです(例: `/var/lib/postgresql/data`)。**アプリの説明書で、データを置く場所を確認**しましょう。
- 1 つのデプロイに、最大 **30 件**まで。同じマウント先は、2 つ作れません。
- [[保存]] → [[反映]]。反映すると、**アプリが作り直されます**。

### 大きくする

ボリュームのパネルで、大きさを、**大きい方向にだけ**変えられます(**小さくはできません**)。[[保存]] → [[反映]](「拡張待ち」の帯が出ます)。

### 消す

:::note warn ボリュームを削除すると、中のデータも消えます。元に戻せません。
大事なデータが入っているときは、削除する前に、アプリの機能で、バックアップを取ってください。
:::

## ConfigMap(設定ファイル)

アプリに渡す、**設定ファイルの、セット**です。たとえば、「nginx の設定ファイル」「アプリの `config.json`」などを、画面から作って、アプリの中の好きな場所に、置けます。

### 作る・編集する

:::steps
1. **[[ConfigMap]] タブを開く**

   プロジェクトの上のタブです。[[作成]]で、名前(英数字とハイフン、64 文字まで)を付けます。

2. **ファイルを足す**

   - **文字を書く** — ファイル名と、中身を入力します。
   - **ファイルをアップロードする** — 画像などの**バイナリ**は、自動で判定して、そのまま渡せます。

   ファイル名は、英数字と `. _ -`(`/` は使えません。フォルダ分けは、アプリに置くときの「マウント先」で、します)。

3. **保存する**

   [[保存]]を押すと、**新しい「版」**ができます。古い版は、消えずに残ります(古い版を開いて、下書きにして、やり直せます)。
:::

| 上限 | 値 |
|---|---|
| 全部のファイルの大きさ(合計) | **1 MiB まで**(バイナリは、変換後の大きさで数えます) |
| ファイルの数 | 50 個まで |

### アプリにつなぐ

デプロイのパネルの [[ConfigMap]] タブで、**どの ConfigMap の、どのファイルを、アプリの中の、どこに置くか**を決めます。

- **マウント先のパス** — 置く場所(例: `/etc/nginx/conf.d/default.conf`)。
- **ファイル名の変更** — 置くときに、別の名前にできます。
- **権限** — [[標準(0644)]]、[[読み取り専用(0444)]]、[[所有者だけ読み取り(0400)]] などから選びます。分からなければ、**標準**のままで OK。

:::note warn 設定ファイルを直したのに、アプリに反映されない?
アプリは、**決まった「版」を、固定して**使っています(動作を、安定させるため)。ConfigMap を編集して、新しい版ができても、アプリは、前の版のままです。**デプロイの ConfigMap タブで、新しい版に切り替えて、反映**してください。
:::
